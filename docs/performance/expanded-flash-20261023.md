# Flash 小任务贯通执行与扩大样本验证

## 问题与改动

上一候选正式 5/5，但总 token 仅降低 2.76%，读取调用合计仍为 11 次。两个小模块分别规划、实现后再集成，共三次建立源码上下文；生成的单元测试也产生语法与无效夹具修补。

本轮按需求规模调度：完整需求不超过 24,000 字符、包含 2–4 个有描述的叶子、原模块覆盖全部需求 ID 时，使用一个 ROOT 实现上下文。不会裁剪需求或改写场景。其他任务维持原调度。联合阶段运行根脚本，最后仍执行需求审核及适用的视觉/公开回归；失败进入原有有界修复流程。

完整成功的通用任务边界检查允许传给紧接着的一次控制器验证，必须同时有 build、test、布局结果，且完整输入指纹和回滚版本均未变化。部分检查、失败、指纹扫描不可用、预算终止、依赖或运行数据变化均不复用。适用公开回归的任务仍要求完整公开结果。

集成阶段直接接收上个边界的具体失败，避免重新发现已知错误。生成提示要求先覆盖真实应用/API 的必要流程、从需求生成有效夹具、一次只变更待测字段；不删除现有测试、不跳过失败、不降低业务要求。

## 交付边界

主线保留隔离执行和完整源码审核修复。平台包显式从原冻结 ZIP 派生，沿用其平台原生执行后端；不是给主线增加本机执行回退。平台包覆盖当前调度、模型策略、读取证据、提示和指纹模块；验证器来自 `ed6f023:agent/verify.py`，具有相同重复脚本合并逻辑。两种后端不能宣称完全相同的环境。

## 主线隔离回归修复

首次 CI 镜像构建因注册表新增 Rollup 4.65.0 而发生 ENOTCACHED：完整元数据宣告的版本超出已缓存锁文件。迁入既有缓存裁剪方法，仅保留锁文件允许版本及标签，无 lockfile 离线安装检查继续保留。新增真实 Vite 传递依赖回归同时发现 /work 默认 noexec 导致 esbuild EACCES；仅容器内 /work 显式允许执行原生构建程序，保持网络隔离、非 root、nosuid/nodev、只读根文件系统及凭据隔离。8 项真实 Docker 回归及 7 项边界单测均通过。该修复不改变本轮已提交的平台冻结后端 ZIP。

## 扩大样本中的首轮观测及修正

候选 v3 的 C1（4f6ca3e26c08）正式 5/5，24 次 Flash 请求、960,336 token、缓存命中率 93.4101%，读取工具合计 4 次；对原冻结单次基线总 token 下降 48.845%。这仍是单次观测，不是稳定收益证明。需求审核连续两次引用无效，保持未通过；前端自测修补也完整保留。因此新增 v4：明确引用原语言、引用文本与节点 ID 对应，并在一次纠错中指出被拒绝的 ID/原引用；不放宽引用匹配，也不增加重试次数。新增回归覆盖错用父节点引用和翻译引用，两者仍拒绝且可以正确纠正。v3 的样本不并入 v4 同包样本。

最终候选 v4 安排 3 次运行；当前仍未满足合并门槛。

## v4 暴露的通过后修改漏洞

v4 首轮 f1511a518322 正式 5/5，56 次 Flash 请求、1,774,492 token、94.8542% 输入命中率、读取 3 次，最终需求审核通过。仅下降 5.48%，未达到期望收益，停止继续重复该版本，保留本次完整样本。日志显示审核给出 repair，但 missing_behavior 明确以 This is not a concrete required-behavior gap. 收尾，控制器仍执行修复；同时按需 verify_candidate 通过后仍允许下一轮请求。

v5 拒绝审核自己撤回的缺陷，仍只允许一次纠错，重复矛盾则保持审核失败，绝不自动转成 pass。按需验证通过后立即交回控制器，不执行同批剩余修改；独立完整边界继续执行，若失败则保持失败。新增回归覆盖中英文撤回缺陷、纠错上限、同批和后续可选修改、边界失败。

此前 v3/v4 均属于开发诊断样本，最终同包重复验证改为 v5 三次，所有已发生的样本保留，不跨版本混算收益。
